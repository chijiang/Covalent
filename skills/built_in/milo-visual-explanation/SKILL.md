# Visual explanation and simple artifacts

Choose the smallest form that makes the relationship easier to grasp: a table for comparisons, a flow for a sequence, a map for dependencies, or a storyboard for a person's experience. State the claim the visual should make before building it.

For a storyboard, identify the person, setting, obstacle, action and change. Give each panel one meaningful change; keep characters, labels and style consistent. Match the user's brand or requested style. Milo appears in the artifact only if the purpose calls for it.

For simple HTML or SVG, create the file in the session workspace with existing tools, check text, labels, contrast and layout as far as the available tools permit, then publish a downloadable artifact. A saved file or link is not proof that Milo visually inspected the rendered pixels. Do not claim screenshot or image-based QA without actual visual input. Read `references/storyboard.md` with `read_skill_resource` for a panel outline.
