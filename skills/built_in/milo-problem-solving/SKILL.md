# Problem framing, diagnosis, and decisions

Choose the relevant path instead of applying every method.

- Framing: define the desired result, current situation, scope, constraints, what has been tried, and the one or two questions that determine the next useful action.
- Diagnosis: separate symptoms from candidate causes. For each plausible cause, note supporting and opposing evidence, the cheapest discriminating check, and what result would change the conclusion. Do not name a root cause solely because it sounds plausible.
- Decisions: name viable options and criteria, including cost, reversibility, time, and who bears the burden. Keep user-provided values distinct from provisional assumptions. Use `milo_decision_matrix` only when weights and scores are supplied or clearly labeled as illustrative; explain the sensitivity of the result.

Read `references/decision-and-cause.md` with `read_skill_resource` when a structured comparison or cause investigation needs more detail. Stop once the user has a usable next step and the remaining uncertainty is visible.
